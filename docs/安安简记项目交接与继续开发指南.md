## 3. 启动模拟器、ADB 与应用

在 PowerShell 执行以下环境设置。此配置适用于当前电脑：

```powershell
$env:JAVA_HOME = 'C:\Program Files\Android\Android Studio\jbr'
$env:ANDROID_HOME = 'F:\AndroidDev\Sdk'
$env:ANDROID_SDK_ROOT = $env:ANDROID_HOME
$env:ANDROID_AVD_HOME = 'F:\AndroidDev\Avd'
$env:GRADLE_USER_HOME = 'F:\AndroidDev\.gradle'
$env:PATH = "$env:JAVA_HOME\bin;F:\AndroidDev\Sdk\platform-tools;F:\AndroidDev\Sdk\emulator;$env:PATH"
```

查看可用模拟器并启动 Android 15 / API 35：

```powershell
& 'F:\AndroidDev\Sdk\emulator\emulator.exe' -list-avds
& 'F:\AndroidDev\Sdk\emulator\emulator.exe' -avd AnAn_API35_Pixel6
```

其他版本把 AVD 名替换为 `AnAn_API29_Pixel6` 或 `AnAn_API36_Pixel6`。在 Android Studio 中也可以打开 **Tools → Device Manager**，在对应 AVD 行点启动按钮。做可重复回归时建议冷启动且不读写快照：

```powershell
& 'F:\AndroidDev\Sdk\emulator\emulator.exe' -avd AnAn_API35_Pixel6 -no-snapshot-load -no-snapshot-save
```

待模拟器启动完成后，在另一个 PowerShell 窗口执行：

```powershell
& 'F:\AndroidDev\Sdk\platform-tools\adb.exe' start-server
& 'F:\AndroidDev\Sdk\platform-tools\adb.exe' devices -l
```

设备状态应为 `device`，而不是 `offline`。截至本指南检查时，AVD 定义可以列出，但当前检查会话的 ADB server 未能正常返回设备清单（出现过 `could not read ok from ADB Server` / `failed to start daemon`）；因此本轮没有声称已启动或操作模拟器。若重试仍失败，先关闭重复的 Android Studio/模拟器进程，再运行 `adb kill-server`、`adb start-server`，检查 5037 端口占用后重试；这属于当前本机连接问题，不足以判定应用代码有缺陷。

构建、安装并启动 Debug 应用：

```powershell
Set-Location 'D:\anan\env-check'
.\gradlew.bat :app:assembleDebug --no-daemon --console=plain
.\gradlew.bat :app:installDebug --no-daemon --console=plain
& 'F:\AndroidDev\Sdk\platform-tools\adb.exe' shell monkey -p com.anan.anannotes 1
```

应用 ID 为 `com.anan.anannotes`。Debug APK 默认输出在 `app/build/outputs/apk/debug/app-debug.apk`。构建物是可重生成产物，不要把 `app/build` 作为源码维护。

## 5. 数据与隐私边界

- 普通笔记存放在应用私有 Room 数据库及应用私有图片文件中，依赖 Android 应用沙箱隔离；**普通笔记没有应用级加密**。不要宣传成“所有笔记均加密”。
- 私密模块单独加密存储；私密笔记主动导出、分享或复制到系统剪贴板后，会离开私密库保护边界。
- OCR 模型随包提供，OCR 在设备本地运行。合成图像测试不能代表所有真实照片或聊天截图的识别准确率。
- 当前 Release 构建已接入 `INTERNET` 权限门禁。历史候选清单还含 `ACCESS_NETWORK_STATE` 等 Android/WorkManager 权限；读取网络状态权限不等于网络访问权限。
- SAF 目标由用户选择；第三方文件 Provider 可能自行同步或备份文件，应用不能控制其策略。
- Android 云备份规则配置为不备份应用数据；这不等同于独立安全审计，也不保证设备系统、剪贴板或外部 Provider 的行为。

## 8. 建议的下一轮顺序

1. 先备份当前源码并恢复 Git 版本控制，记录当前基线；不要先改皮肤、加功能或生成新的正式签名包。
2. 修复本机 ADB/JDK 环境问题，在 API 35 AVD 上执行新鲜单测、Lint、Debug 构建和 UI 冒烟。
3. 优先处理皮肤底图与 A4 600 DPI 导出的清晰度及视觉一致性；用固定测试笔记覆盖 11 款皮肤和各导出尺寸。
4. 在 API 29、35、36 重跑全量功能矩阵和分阶段恢复 fixture，然后由用户在最终小米真机完成真实分享、SAF 与视觉验收。
5. 所有阻断项关闭后，递增版本号、使用用户控制的发布密钥签名，再生成权限清单、依赖清单、断网结果和 SHA-256。未签名候选包只用于审查，不作为公开分发物。
