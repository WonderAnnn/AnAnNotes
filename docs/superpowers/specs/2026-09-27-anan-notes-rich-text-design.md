## 1. 目标与范围

为安安简记的混合编辑器补充轻量文字格式，让格式能随笔记保存、恢复和在编辑器中继续修改。数据保留为普通文本，格式用独立的 UTF-16 区间元数据描述；不得把 Markdown 标记混入正文。

V1 实现范围：

- 内联格式：加粗、斜体、删除线；三种格式可叠加。
- 块级标题：一个标题级别，作用于当前文字块。
- 引用：沿用独立的 `QUOTE` 内容块；可与内联格式叠加，但不与标题样式叠加。
- 编辑体验：有选区时格式化选中文本；无选区时切换后续输入格式，直到再次切换。
- 普通笔记、编辑草稿和私密笔记均可往返保存格式；旧数据默认无格式。

待办、分割线和图片仍由各自内容块操作负责，不在本设计中实现。图片 OCR 生成的文字块可在 OCR 完成后作为文字内容编辑和应用内联格式；OCR 初始结果保持纯文本。V1 不提供字体颜色、局部字号、下划线、多个标题级别、手写或 Markdown 源码编辑，也不实现导入、OCR、PDF/PNG/TXT/Markdown 导出本身。

## 2. 已确认的产品决定

| 项目 | 决定 |
|---|---|
| 数据模型 | 原始文本与格式区间分别保存；不把格式编码进 Markdown 正文 |
| 选区格式行为 | 有选区时处理选区；无选区时切换持续生效的后续输入格式 |
| V1 工具范围 | 加粗、斜体、删除线、单级标题、引用 |
| 其他内容 | 待办、分割线、图片维持独立内容块和既有路线 |
| 主题颜色 | 编辑器显示颜色从当前皮肤读取；不把颜色写入每段格式数据 |

## 3. 编辑器行为

### 3.1 内联格式与光标

加粗、斜体、删除线分别独立开关，支持组合，例如同一段文字可同时加粗和斜体。

- **选区非空：** 工具栏按钮显示选区状态。若选区内所有字符都已有该格式，点击移除该格式；否则将该格式应用到整个选区。混合状态点击后统一应用，而不是只反转其中一部分。
- **没有选区：** 点击按钮为当前编辑会话设置该格式的输入覆盖状态。覆盖状态持续到用户再次点击同一按钮；打开另一条笔记或结束当前编辑会话后不保留。对其他选区执行格式操作不会清除这一覆盖状态。
- **输入继承：** 未被输入覆盖状态明确指定的格式，按插入点相邻字符继承；文本起始处继承右侧字符格式，没有相邻字符时为普通文本。显式开启/关闭覆盖状态优先于继承结果。
- **光标状态：** 未选中内容时，工具栏按有效输入格式显示；存在选区时显示全选中、未全选中或混合状态。用户点击混合状态按钮时统一应用该格式。
- **格式操作不改变正文：** 格式化空选区之外的文本不插入 Markdown 符号，不修改正文内容和笔记标题。

打开笔记时不恢复上次会话的临时输入覆盖状态；持久化格式只由已有字符范围决定。保存正文、选区和格式元数据必须作为一次编辑状态变更处理，不能先更新正文、稍后才异步写入选区造成光标跳动或格式区间错位。

### 3.2 标题与引用

- H 按钮只支持一个语义标题级别，应用到当前文字块整体（即使当前只有局部选区）；再次点击恢复普通正文。
- 标题是文字块的展示属性，不是笔记标题字段，不会覆盖首页卡片标题，也不触发“首行自动标题”以外的规则。
- 引用是独立 `QUOTE` 内容块。引用操作将当前文字块在 `TEXT` 与 `QUOTE` 间转换；反向转换恢复普通文字块。转换保留原文本及内联格式区间。
- 标题和引用互斥：`QUOTE` 块使用引用展示，不能再同时标为标题。图片、待办、分割线及其他不适用的块不显示文字格式操作。
- 标题的字号、字重和行高由编辑器的统一标题样式令牌决定，并跟随系统字体缩放；文字颜色使用当前皮肤正文色。引用使用当前皮肤的正文色和低干扰引用标识，不引入固定黄色或全屏强调色。

### 3.3 输入、选择替换与内容块操作

`EditorTextState`（目标接口）是单个文字块的编辑状态所有者，至少包含纯文本、`TextRange` 选区、格式区间、IME composing 区间和本次编辑会话的输入覆盖状态。UI 以一份原子状态更新提交正文、选择和格式，避免当前分开的正文/光标回调产生竞态。

插入、删除、选区替换、粘贴、撤销/重做及 IME 组合提交均须同步调整格式区间。普通粘贴只接收纯文本；插入字符遵循 3.1 的覆盖和继承规则。IME composition 尚未确认时，不提交可能被输入法撤销的临时格式边界；提交或取消后状态与显示文本一致。用户明确点击保存或返回时，编辑器先结束当前 composition，再保存最终文本与格式。光标和区间偏移以 UTF-16 为准，并禁止落在代理项对中间。

图片仍是独立内容块。将图片插入文字块中间时，文字块按插入点拆分：前半段沿用原块 ID，后半段使用新 ID，图片位于两者之间；原块每种格式只保留落在对应文本片段内的部分，后半段区间重新从 0 计数。跨选区插入时选中文本先被替换，随后按相同规则拆分。该规则只约束格式数据在既有插图操作中的一致性，不扩大本阶段的图片功能范围。

拆分时不创建空文字块：只剩一个非空文字片段时由该片段沿用原 ID；左右片段都非空时左侧沿用原 ID、右侧分配新 ID；两侧都为空时只插入图片块。格式化空文字块或切换临时输入覆盖状态不算笔记内容，不能让“没有内容就不保存”的规则失效。

## 4. 数据结构与序列化

### 4.1 Kotlin 模型

目标模型放在 `core/model/BlockModels.kt`，供普通和私密编辑共用：

```kotlin
enum class InlineStyle { BOLD, ITALIC, STRIKETHROUGH }
enum class TextBlockPresentation { BODY, HEADING }
enum class FormattingDecodeError {
  UNSUPPORTED_VERSION, MALFORMED_DATA, LIMIT_EXCEEDED, INVALID_RANGE, INVALID_BLOCK_STYLE,
}

data class InlineStyleRange(
  val startUtf16: Int,
  val endUtf16: Int,
  val style: InlineStyle,
)

data class BlockFormatting(
  val presentation: TextBlockPresentation = TextBlockPresentation.BODY,
  val inlineStyles: List<InlineStyleRange> = emptyList(),
)

sealed interface BlockFormattingState {
  data class Supported(val value: BlockFormatting) : BlockFormattingState
  data class Unsupported(val originalBlob: ByteArray, val error: FormattingDecodeError) : BlockFormattingState
}
```

`NoteBlockDraft` 和 `BlockModel` 增加默认值为 `Supported(BlockFormatting())` 的字段。`BlockEntity` 继续单独存放 `text`，增加可空 `formattingBlob`（SQLite BLOB，Room 默认值为 `NULL`）；`NULL` 等价于普通正文、无内联格式。Room mapper 是模型与字节编码间唯一的转换边界。`QUOTE` 的块类型负责引用语义；引用块格式对象的 `presentation` 必须为 `BODY`。`Unsupported` 保存不可变的原始字节副本和稳定错误码，供旧版应用无损保留未知格式。

V1 只允许 `TEXT`、`QUOTE`、`OCR_TEXT` 保存内联格式；仅 `TEXT` 可使用 `HEADING`。其他块的格式必须为空。新建和旧数据均得到显式默认格式，调用方不得用 `null` 表示未知或损坏格式。

### 4.2 区间不变量

- 区间采用半开区间 `[startUtf16, endUtf16)`，索引单位与 Kotlin `String` 和 Compose 选择一致。
- `0 <= startUtf16 < endUtf16 <= text.length`；不得跨出文本或切开 UTF-16 代理项对。来自 UI 的选区若落在代理项对中间，格式化范围向外扩到完整字符；折叠光标吸附到该字符前的安全边界。
- 不同样式可重叠；同一样式的区间不得重叠或相邻，规范化时合并为最大连续区间。
- 列表按 `startUtf16`、`endUtf16`、`style` 稳定排序。无效输入须在进入仓库前拒绝，不能静默截断成看似有效的数据。
- 每块最多 100,000 个区间，格式 blob 最大 4 MiB；草稿/私密快照整体编码受既有 64 MiB 文件/快照上限约束。编码长度、计数和偏移均须校验后再分配内存。

区间不保存字体名、字号、颜色、皮肤 ID 或正文副本。显示阶段由纯文本、区间与当前皮肤合成 Compose `AnnotatedString`；搜索仍索引纯文本。

### 4.3 稳定字节格式

新增共享 `BlockFormattingCodec`，目标文件为 `core/model/BlockFormattingCodec.kt`，采用有魔数、显式版本、固定枚举 ID、长度边界和尾随数据检查的二进制格式。首版格式版本为 1，编码顺序为：4 字节 ASCII 魔数 `ANFM`、版本、块展示枚举、区间计数，以及每个区间的起点、终点和样式枚举。不得依赖 Kotlin enum ordinal；枚举 ID 一经发布不可复用。

`formattingBlob = NULL` 表示无格式。已知格式损坏或不受支持时，正文仍可读取，但不得把错误当作空格式自动覆盖原字节：对应块保持只读并可复制，其他块仍可编辑；编辑器提示可恢复错误，并要求用户明确选择“移除不兼容格式并继续”后才允许清除该块格式元数据。草稿和私密快照 codec 按长度边界原样保留 `Unsupported.originalBlob`。如果私密快照自身的魔数、版本、长度或结构校验失败，则作为私密快照完整性错误处理，不回退成可保存的空笔记。未知格式 blob 不得由旧版应用解码后重写。

## 5. 模块关系与持久化边界

| 模块 | 富文本职责 | 持久化/隔离要求 |
|---|---|---|
| `core/model` | 样式枚举、块展示、范围校验/规范化、纯函数文本编辑变换 | 不依赖 Android UI、Room 或私密密钥 |
| `feature/editor` | 选区、IME、输入覆盖状态、工具栏和块转换 | 普通编辑写普通仓库与普通草稿；私密编辑只写私密接口 |
| `data/local` / mapper | `formattingBlob` 映射及 schema 迁移 | 新增 Room v5→v6；不得把格式化正文复制到其他表 |
| `feature/private` | 私密块格式读写 | 格式数据只在加密私密快照明文内存期间存在，不进入普通 Room、FTS、草稿、缓存或日志 |
| 搜索 | 读取标题和块的纯文本 | 格式范围和展示属性不参与索引或查询 |
| 导出 | 后续按格式呈现/转换 | 本阶段只冻结转换契约，不实现导出管线 |

普通数据库从 Room v5 迁移到 v6 时，以显式迁移给 `note_blocks` 增加 nullable `formattingBlob` 列；旧块取 `NULL`，不改写正文、标题、图片路径、块 ID 或 FTS 内容。`MIGRATION_5_6` 加入数据库构建器，并导出/核对 Room schema。FTS 查询和迁移无需为了标题展示属性改写：标题仍是 `TEXT`，引用仍为 `QUOTE`，索引继续读取原始文本。

普通编辑草稿 `ANAN` codec 从 v2 升至 v3。v1/v2 解码时所有块使用 `Supported(BlockFormatting())`；v3 读写格式数据，并对 `Unsupported` 原样保留格式 blob。旧草稿只有在正常成功保存后才清理，不能因升级读取而提前删除。私密快照 `ANVS` 从 v1 升至 v2；v1 仍可解码，旧块默认无格式；v2 包含相同的格式语义。外层私密记录 `ANPR` 格式保持不变，解密后的 `ANVS` 内容仍只通过私密加密存储持久化。旧私密快照只在用户完成一次成功私密保存后以 v2 重写，解锁/读取本身不得改写快照。普通草稿绝不承载私密正文或私密格式数据。

## 6. 搜索、恢复和导出契约

- 搜索与首页摘要使用去格式纯文本；标题样式、加粗、斜体和删除线均不改变命中内容。搜索结果的匹配高亮是临时 UI 样式，不写回笔记格式区间。
- 自动保存与崩溃恢复须在同一个块快照中保存纯文本和格式。恢复后区间经校验并与恢复文本匹配；无效区间不能静默套用到正文。
- 普通与私密编辑均保持既有版本冲突语义。格式变化属于笔记内容变化，正式保存时随文本和块同事务提交、递增 `contentRevision`；格式元数据写失败时不能报告保存成功。
- 后续 PDF 和 PNG 按当前皮肤、字体及格式绘制；TXT 输出纯文本；Markdown 输出常见 `**bold**`、`*italic*`、`~~strike~~` 标记，块级标题输出一个 `# `，引用输出 `> `。组合格式必须稳定、可逆地嵌套；如果字符本身含 Markdown 标记，转义规则由导出实现测试冻结。
- 本设计不改变 600 DPI 分页 PNG、长图、1080 × 1080/1080 × 1350 社交图片、PDF 原文和导出提示规则；不表示这些格式当前已实现。

## 7. 错误处理与安全边界

- 正文与格式元数据分开保存；数据库事务、草稿原子文件写入或私密快照加密写入失败时，不得仅保存其中一半并报告成功。
- 新生成的格式范围非法、块类型不允许该展示样式、计数超限、偏移越界或 UTF-16 代理项边界非法，均拒绝该格式变更并保留上一份有效数据。载入到未知版本的原始 blob 时，将其作为 `Unsupported` 原样保留；该块保持只读，其他块可保存，直到用户明确确认移除该块的未知格式。
- 普通格式 codec 错误不得崩溃首页或丢弃正文；需在对应编辑块提供明确恢复选项。私密加密快照错误不得降级写入普通区域或把解密内容写入日志。
- 不增加网络权限、不调用 OCR/云端格式化服务、不新增遥测。异常和日志只能记录稳定错误码，不记录正文、标题、选区内容、私密元数据或密钥。
- 私密内容在解锁后可在内存中显示格式；锁定、后台及最近任务预览继续遵循总体技术设计中的清屏与遮挡规则。格式元数据不能绕开私密访问令牌或复用普通缓存。

## 8. 测试与验收

### 8.1 纯 JVM 单元测试

- 范围规范化、同样式合并、异样式重叠、局部应用/移除、混合选择状态和边界拒绝。
- 插入、删除、选区替换、粘贴及撤销/重做后的格式偏移保持正确；空文本和空格式不生成零长度区间。
- 中文、ASCII、emoji（代理项对）、组合字符、换行与行尾选择；任何编辑都不产生越界或代理项中间偏移。
- 文字块正文/标题切换和 TEXT/QUOTE 转换保留 ID、正文和内联格式；引用与标题互斥。
- 图片插入导致文本块拆分时，左右区间正确裁剪/重基，图片不携带文本样式。
- `BlockFormattingCodec` 往返、未知版本、截断、非法枚举、超限计数、尾随字节与损坏输入；未知/损坏原始 blob 在不触碰该块时可在普通草稿与私密快照中无损往返，显式移除后仅清除对应块元数据。

### 8.2 Android/Room/Compose 集成测试

- Room v5→v6 迁移保留所有笔记、块、待办、FTS 搜索结果，并将旧块格式读为默认 BODY/空区间。
- 草稿 v1/v2 fixture 可恢复为无格式；v3 格式快照往返，原子保存后仍可恢复；无效格式草稿保留文件并显示可处理错误。
- 私密 `ANVS` v1 fixture 可在隔离存储中读取；v2 格式保存/重新打开一致；锁定时普通 Room、FTS、文件名、普通草稿和日志中均无私密正文。
- UI 有选区和无选区两种模式切换 B/I/S；连续输入、光标移动、取消选择、键盘/IME 组合输入后，按钮状态、正文、选择和格式一致。
- 大字号、深色模式和不同皮肤下，标题/引用/内联格式仍可读，选中态颜色来自皮肤而非固定黄/蓝。
- 自动保存、异常恢复和并发冲突路径验证格式与纯文本一起提交；格式写入失败不得丢弃可恢复草稿。

### 8.3 验收条件

1. 旧数据库、旧草稿和旧私密快照可以在不改动正文的前提下按无格式打开。
2. B/I/S 支持选区格式化、叠加和持续输入；选择范围及 emoji 边界稳定。
3. 标题和引用操作符合块级互斥规则，格式转换不丢文本或稳定块 ID。
4. 搜索只匹配原始正文，不把视觉格式或 Markdown 标记写入索引。
5. 普通及私密数据各自留在原存储边界；所有相关迁移、codec、编辑器和设备测试通过。
6. 导出只按第 6 节定义的目标转换；导出实现及分辨率/内存验收另按既有计划执行。

## 9. 分阶段落地建议

本节仅给实现计划提供边界，不替代实现计划或表示开发已经开始。

1. 先做纯 Kotlin 区间模型、规范化、编辑变换与测试。
2. 加普通块映射和 Room v5→v6 migration，验证旧库与搜索不变。
